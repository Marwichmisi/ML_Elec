<objective>
Build the MQTT bridge plugin (ACQ-01, ACQ-02): an external child process with an embedded mochi-mqtt broker, paho MQTT client, three-level data validation, JSON and binary payload parsing, and NATS publishing. The plugin bridges ESP32 sensor data from MQTT into the core NATS bus.

Purpose: This is the primary data acquisition path for the system. ESP32 sensors publish MQTT messages that flow through this plugin into the NATS bus for storage and anomaly detection.

Output: Compilable MQTT plugin binary that starts a broker, subscribes to topics, validates data, and publishes to NATS.
</objective>

2. Create `cmd/mqtt-plugin/main.go`:

   a. App struct (per PATTERNS.md cmd/mqtt-plugin pattern):
   - Config *config.Config
   - Broker *mqtt.Server (mochi-mqtt)
   - Client mqtt.Client (paho)
   - NATSConn nats.Conn (to publish sensor data)

   b. StartBroker function (per RESEARCH Pattern 2):
   - Create mochi-mqtt server with InlineClient: true (RESEARCH Pitfall 7)
   - Add auth.AllowHook (no auth for v1, per SPEC out-of-scope)
   - Add TCP listener on configured port (D-02: default 1883)
   - Start server in goroutine
   - Return server instance

   c. ConnectClient function (per RESEARCH Pattern 3):
   - Create paho client options: AddBroker, SetClientID, SetCleanSession(false), SetAutoReconnect(true), SetKeepAlive(30s)
   - SetWill for LWT: "sys/mqtt-plugin/status" = "offline", QoS 1, retained (D-18)
   - Connect to local broker
   - Publish "online" to status topic
   - Return client

   d. SubscribeAndBridge function:
   - Subscribe to configured topic (default "esp32/#") with QoS 1
   - On message callback:
     1. Determine payload format from topic or config
     2. Parse JSON or binary payload
     3. Run three-level validation (per D-22)
     4. If valid: publish to NATS "sensor.{sensor_id}" with QoS matching MQTT QoS
     5. If invalid: log rejection reason (per SPEC prohibition: never silent)
   - Store last timestamp per sensor for monotonicity check

   e. JSON parsing (per D-13):
   - Parse {"ts": ..., "values": {"temperature": ..., "humidity": ..., "current": ...}}
   - Extract timestamp and values
   - Validate all fields present (reject missing)

   f. Binary parsing (per D-12, RESEARCH Pattern 4):
   - BinaryHeader: 28 bytes (version 1, sensor_type, encoding, reserved, timestamp int64, sample_count uint32, sample_rate uint32, reserved[8])
   - Big-endian only (SPEC: reject unknown endianness)
   - Parse vibration samples as int16 array
   - Validate header version (must be 1)
   - Validate payload length matches sample_count * bytes_per_sample

   g. Three-level validation (per D-22):
   - Level 1 (Range): Check each value against configurable min/max per sensor type
   - Level 2 (Timestamp): Check timestamp not in future (max 5s drift), not too old (max 24h), monotonicity per sensor
   - Level 3 (Quality): Check payload not empty, not too large (configurable max), sensor health
   - All thresholds from config.yaml (per D-20)

   h. main() function:
   - Structured logging (slog, per established pattern)
   - Load config
   - Signal handling (signal.NotifyContext)
   - Start broker → connect client → subscribe → bridge
   - Wait for shutdown
   - LIFO shutdown: client disconnect → broker stop

   i. go-plugin registration:
   - Implement PluginLifecycle interface (Init/Start/Stop) from pkg/sdk/v1
   - Init: parse config map, apply to MQTT/Validation settings
   - Start: start broker, connect client, subscribe
   - Stop: disconnect client, stop broker
   - Serve via goplugin.Serve with GRPCPlugin (per D-07)
